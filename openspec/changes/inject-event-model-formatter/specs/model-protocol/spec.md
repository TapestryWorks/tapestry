# Spec Delta

## MODIFIED Requirements

### Requirement: 模型请求内容
模型请求 SHALL 携带可选的 system prompt、本次调用截至发起时的完整有序线程事件快照、可用工具规格和迭代序号，以 `events` 替代 `history` 字段。不允许使用工具时，工具规格 MUST 为空。除独立的 system prompt 外，模型输入提示 MUST 来源于事件快照，MUST NOT 通过独立 history 或隐藏的提醒旁路注入。

#### Scenario: 强制收尾请求
- **WHEN** 系统发起超限后的强制收尾调用
- **THEN** 请求的工具规格为空，事件快照包含此次调用前记录的收尾提醒事件，格式化后的消息以有效的收尾提醒结尾

#### Scenario: 跨回合事件快照
- **WHEN** 同一线程在第二个回合发起模型请求
- **THEN** 请求包含此前回合及当前回合截至本次调用的全部事件，并保持日志顺序，调用后的事件不改变该请求快照

#### Scenario: 空事件请求
- **WHEN** 调用方构造没有对话事件的模型请求
- **THEN** 请求允许携带空事件列表，system prompt 和工具规格仍独立保留

### Requirement: 模型请求与响应可序列化
模型请求与模型响应 MUST 支持序列化，序列化后再反序列化 SHALL 得到相等的值。模型请求的序列化表示 MUST 包含 `events` 而不包含 `history`，并保留事件信封与载荷中的结构化信息。

#### Scenario: 请求往返
- **WHEN** 序列化并反序列化一个包含用户消息、工具调用和工具结果事件的模型请求
- **THEN** 结果与原值相等，事件顺序、关联 ID、日志位置、时间戳和载荷不变

#### Scenario: 请求线格式
- **WHEN** 序列化带系统提醒事件的模型请求
- **THEN** 输出包含 `events` 字段且不包含 `history` 字段，提醒仍是结构化事件而非预渲染文本

## ADDED Requirements

### Requirement: 模型初始化支持格式化策略注入
提供方模型 SHALL 支持在初始化时注入事件到模型消息的格式化策略，并在后续每次流式和非流式调用中使用该实例。未显式注入时，现有便捷构造入口 SHALL 使用默认策略。调用方 MUST NOT 为使用自定义策略而预先生成提供方消息。

#### Scenario: 自定义策略影响实际请求
- **WHEN** 初始化模型时注入把用户内容转换为可识别标记的策略，然后提交内部事件
- **THEN** 实际发给提供方的请求消息包含该标记，而非固定映射生成的原内容

#### Scenario: 流式和非流式一致
- **WHEN** 对同一模型使用相同事件分别发起流式与非流式调用
- **THEN** 两种调用均通过初始化时注入的策略转换消息，system prompt 和工具规格保持一致

#### Scenario: Chat 与 Responses 一致支持
- **WHEN** 分别初始化 OpenAI Chat 模型和 OpenAI Responses 模型并注入自定义策略
- **THEN** 两种模型各自的实际请求都使用注入策略，且仍访问各自原有端点

#### Scenario: 默认构造入口
- **WHEN** 调用方通过不指定策略的便捷入口初始化模型
- **THEN** 请求使用默认策略，遵循会话历史的提醒筛选与工具结果补全契约
